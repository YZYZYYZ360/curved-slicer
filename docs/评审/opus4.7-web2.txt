## 开篇：v6.1 vs v1 的进步与残留病灶

**实质性进步**（必须承认）：
1. ✅ 撤回"拓扑等价"claim → 改为实验性质
2. ✅ 撤回"首次"claim → 改为窄 claim（pointwise IK margin）
3. ✅ C2 IK 检查从"逐 voxel 局部"升级为"路径级 Viterbi DP"（开篇缺陷 #1 修复）
4. ✅ 引入 capability table 而非数值对比 → 避免与 Jayakody/Li 直接对位
5. ✅ 引入 RegularizationReport 量化 mao 偏差 → 把"打不出来"转成"几何代价可报告"
6. ✅ TransitionPlanner 6 keypoint + 4 级 fallback → 同层/跨层自碰撞有了处理框架
7. ✅ Fallback 阶梯设计（L4/L3/L2）→ 工程风险可控

**残留的根本性病灶**：

### 病灶 A：Pass 3 的 IK 可达性场 **p_ik 严重低估了可达性失败的全局耦合**

你的 p_ik(v) 是 "对每个体素，遍历 12 yaw × 8 branch，取最小 J_ik"。这是**该点的存在性可达**，不是**路径上的可达**。Viterbi DP 在 Stage 5 才检查路径连续性。

问题：Stage 2 的 D_final 用 p_ik 作权重 → **生成的层会偏向"每个点单独可达"的区域** → 但单点可达不蕴含整层路径可达。最坏情况：
- 一层内每个点 p_ik 都很低（看似很好）
- 但相邻点的 best branch 总是不同（分支跳变频繁）
- Stage 5 DP 发现整层无连续解 → 整层标 IK_FAIL

**等价表述**：你只对约束的 0-阶（存在性）做了 field bias，对 1-阶（连续性）什么也没做。

修复成本：在 p_ik 中加入**分支一致性项**——例如 p_ik_consistency(v) = 邻域内最优 branch 的"主导比例"，鼓励层穿过 branch 单一的区域。这是非平凡的实现，但 v6.1 没写。

### 病灶 B：Pass 1 / Pass 4 用 **D_0_mm（毫米）作为 Marching Cubes 等值面源**，但权重 w 是无量纲缩放过的

仔细看：
```
w(u,v) = ‖u-v‖ × [1 + α·p_clear + β·p_orient + γ·p_curv + δ·p_ik(v)]
```

`‖u-v‖` 单位 mm，但 `[1 + ...penalty...]` 是无量纲乘数。所以 D_final_mm 不是真实毫米距离，而是**"沿最短路径累计的、被罚项膨胀过的等效距离"**。

然后你在 Stage 3 用 `D_final_mm = k × layer_height_mm` (1.2mm) 提取等值面。这意味着：
- 在低惩罚区，1.2mm 对应真实约 1.2mm 几何距离
- 在高惩罚区（penalty=5），1.2mm 对应真实约 0.24mm 几何距离 → 层薄得离谱
- 反过来，要打满 1.2mm 真实层厚的高惩罚区域，需要 D_final 累积到 6mm → 该区域被跳过，层间断了

**所以你的 layer_height_mm 在 D_final_mm 语境下不是物理层厚，是"加权距离层厚"。物理层厚在高惩罚区会显著偏薄**，导致 bead overlap、layer broken。

这不是数学错误（Dijkstra 形式上没错），是**语义错误**：你给一个加权距离场起了 `_mm` 的名字，又用它直接当物理厚度切。要么：
- (a) 在等值面提取前做**重距离化**（reinitialize to true Euclidean SDF in band），损失加权信息但层厚物理正确
- (b) layer_height 也按 voxel 局部权重缩放：`layer_height_eff(v) = layer_height_mm × w_local(v)`，但这又导致层数依赖路径

v6.1 没看到这个问题的处理。审稿人一旦盯上单位，会要求复现 "实际层厚 vs 名义层厚" 的散点图。

### 病灶 C：M0 Planar-Z baseline **不公平**

你在 M0 写 "自己实现 planar slicer，**同 IK DP + collision validation pipeline**"。听起来公平，实际不公平：

- Planar-Z 切平面层，每层是平面切片 → 在凹腔上方必须有支撑
- 你的 IK DP + collision validation 是设计来检查"无支撑曲面层"的
- M0 在 mao 上必然大面积 collision fail / IK fail（因为悬空体素无前层支撑）
- 这个对比的结论会是 "Planar-Z 在六轴 + 无支撑场景下崩了" → **废话**，本来就不为这个设计

你需要的 baseline 是**和你算法目标场景一致**的方法。建议替换 M0：
- M0' = **Wang 2018 风格的 ASN 贪婪**（你 v1 的 prior，工程量适中）
- 或 M0' = **CurviSlicer (Etienne 2019)** 的复现（如果工程允许）

否则 reviewer 1 会说："你的 baseline 是 strawman"。

## 1. 算法层面的细节缺陷

### 1.1 Pass 2 工具姿态：tool_z = -∇D_0，**这不一定是物理合理的喷嘴方向**

你写 `tool_z(v) = -normalize(∇D_0(v))`。逻辑是"喷嘴朝向距离场来源方向"。问题：

- ∇D_0 是**加权距离场**梯度，不是几何梯度
- 在惩罚剧烈变化的区域，∇D_0 主要反映惩罚梯度，与几何法线脱钩
- 工具姿态偏离曲面法线 → 喷嘴侧壁刮到表面、bead 形状畸变

你的 pitfall #1 提到了这个"鸡生蛋"，处理是"不迭代，δ 太大就降低"。**这是回避，不是解决**。

**建议**：tool_z 用**几何法线**（来自 SDF 的 ∇SDF），而非 D_0 梯度。Pass 2 的 tool_z 估计应该独立于加权距离场。这只是一行代码改动。

### 1.2 Pass 3 yaw 采样均匀分 12 等份的合理性

12 个 yaw = 30° 间距。问题：

- KR4 R600 在某些工作空间区域，腕奇异邻域 yaw 窗口宽度可能 < 30° → 全 12 个采样都落入或都落外
- 30° 是凭直觉选的（圆周 360/12），没有 sensitivity analysis
- "失败段 12 → 24" 也是凭直觉

**建议**：至少在 Week 4 做一次 yaw 采样密度 vs IK 成功率的曲线，附录里挂这条曲线，比纯 magic number 强很多。

### 1.3 IK J_ik 的权重 a, b, c **完全没定义**

你写 `J_ik(q) = a·jl_penalty + b·sing_penalty + c·ws_penalty`。a/b/c 是什么？你的整套加权场 αβγδ 还在论文里要 ablation，J_ik 内部又埋了 3 个 magic weight。**这是嵌套黑盒**。

而且 jl_penalty / sing_penalty / ws_penalty 量纲各异：
- jl_penalty 通常用 (q - q_lim)² / range² 量纲化（无量纲）
- sing_penalty 用 σ_min^{-1} 或 1/cond(J)（单位 rad⁻¹ 或无量纲）
- ws_penalty 是 (‖p‖ - r_safe)² 量纲 mm²

**这三个加起来没有物理意义**。需要至少：每项 normalize 到 [0,1]。

### 1.4 Cyclic DP 的"枚举起点"复杂度

"闭合曲线 cyclic DP（枚举起点）" → 复杂度从 O(K²N) 变 O(K³N) = 1728·N。在 mao 0.8mm voxel + 上千闭合等值线下，这个数字会很糟糕。

而且更糟的是：**多数 cyclic 闭合的 DP 在起点选错时给出局部最优解**，不是全局最优。Bellman 算法在 cyclic 上需要展开 2N 长度 chain + 边界约束（参考 Bellman 经典处理），不是简单"枚举起点"。

**建议**：要么用 fixed-point iteration（2 次 open DP），要么明确说"approximate cyclic DP"并报告 closure gap。

### 1.5 Raster fallback 的 PCA 间距补偿

`Δs = line_spacing × clamp(g_med, 0.5, 1.0)` 中 g_med 是什么？没定义。猜测是"测地距离梯度的中位数"或"局部展平度量"。**没定义的 magic factor 在论文里直接被 reviewer 揪出来**。

而且 raster fallback **退化到平面切的本质**：你用 PCA 找主平面，然后做 plane-family intersection。在强曲面区域（armadillo 头部、mao 头顶）PCA 主平面方向不稳定，导致 raster line 不沿等高线，**变成弯曲面上的螺旋**，bead overlap 失控。

### 1.6 Inter-layer support check 的判据

"每层每点查 layer_{k-1} 最近距离 ≤ support_radius" — support_radius 是多少？没定义。

ASN 是结构判据（拓扑邻接），support_radius 是距离判据（度量邻接）。**两者不等价**。你 Stage 3 用距离判据替代 Stage 2 应该保证的 ASN 判据 → 可能在 Pass 4 的 D_final 上提取出违反 C1 的层。

后续 Stage 4 path generation 才发现 → 标 BROKEN_LAYER → KRL 不输出 → 该层被跳。**算法的"约束 bias"承诺在这里漏底**。

**建议**：Stage 3 提取每层后立即做 ASN check（顶点级或体素级），不能依赖 distance proxy。

## 2. 实验与对照

### 2.1 4 methods × 3 models = 12 runs **数量太少**

按 SCI Q4 / EI 标准这是底线。如果 Week 10-11 出现任何异常，没有 buffer。

更糟的是**消融的维度只有 δ**。审稿人会问：
- "α=0 vs α=α*" 呢？（clearance 的贡献）
- "β=0 vs β=β*" 呢？（orientation 的贡献）
- "γ=0 vs γ=γ*" 呢？（curvature 的贡献）

你的回答是"固定 αβγ 只 ablation δ"（pitfall #8）。这意味着 **α/β/γ 是"凭信仰"放进 field 的，不可证伪**。reviewer 一旦问"你怎么证明 β 不是 0 也行"，你没法回答。

**建议**：至少 α/β/γ 各做一次 0 vs default 的对照（即 4 个变量 × 2 水平 = 16 runs，可以用 Plackett-Burman 减到 8 runs），加上 δ 的全扫，**总 runs 不超过 24**，但消融完整度大幅提升。

### 2.2 mao_regularized 的"smoothing 强度参数"在 OPEN-1 留到 Week 10 决定

意味着 **Week 11 全 matrix 跑之前**，你的 mao 模型还没定型。如果 Week 10 实测发现 95% pointwise IK pass 需要把 mao 抹到 "扁圆球"，那论文里展示的 mao 还能叫 mao 吗？

更严重：**Reviewer 会问 "smoothing 强度是为了让算法看起来 work 而调的吗"**。这是 hyperparameter mining 的指控。

**建议**：smoothing 强度独立于 algorithm performance 选择。例如：固定为"抹平 < r_n/2 = 5mm 细节"（你已写），且**不再为 95% IK pass 调整**。如果调整后的 mao_regularized 仍然 50% SHADOW，那就报告 50%，承认 limitation。

### 2.3 bunny 实机打印的"成功"定义

"低速实机打印一件"——什么叫"成功"？
- 完整打印未中断？
- 几何精度 ≤ Hausdorff 1mm？
- 表面无明显瑕疵？

OPEN-3、OPEN-4、OPEN-5（TCP 校准、r_n、平台坐标）都到 Week 10 决定。如果校准误差 > bead width，bunny 实机可能"打出来但拓扑变形"。论文里展示的"bunny 实物照"如果有明显瑕疵，**审稿人质疑算法可用性**。

**建议**：定义 "physical print success criteria" 写入 Week 10 计划：例如 "Hausdorff distance to nominal STL ≤ 3mm AND no layer separation AND visible bead overlap ≥ 50%"。事先写死，不许事后调。

### 5.3 Capability table 的 "evaluated" 列

```
| Ours | ✓ | evaluated | evaluated | pointwise KR4 | ✓ |
```

"evaluated" 这个词在表里**很弱**。审稿人会理解为 "我们检查了但不保证"。建议改为更具体的措辞：

你列的 6 条 limitation 是诚实的。但"Algorithm bias only, not constraint guarantee" 这种写法**可能被审稿人攻击**："那你的算法到底保证什么？"

## 6. 仍未解决的根本问题（你应该自己也知道但要再次确认）

### 6.1 同层自碰撞

v6.1 的 collision validation 是 "vs printed BVH"。printed BVH 在层内打印过程中**动态增长**：第 k 层的第 i 个 bead 打完后，第 k 层的第 i+1 个 bead 的喷头要避开第 i 个 bead。

你的 Stage 6 Level 2 "Capsule sampling vs printed BVH" 是基于 **previous layers BVH** 还是 **incrementally updated within layer BVH**？

- 如果前者：同层自碰撞**漏检**
- 如果后者：BVH 需要按 path point 递增 rebuild → 这是 expensive 操作，论文没提

**Pitfall #5 说**："按 layer rebuild，不做 per-frame 增量"——所以**是漏检的**。

这是开篇缺陷 #2 的残留。Stage 6 Level 3 "post-quintic dense validation" 也是基于 SDF + 关键帧 FCL，SDF 是 voxelized printed region（按层），同样不含同层增量。

**结论**：v6.1 的 collision validation 在**同层内自碰撞**上是有 blind spot 的。

**对策选项**：
- (a) 接受这个 blind spot，在 limitation 明写 "intra-layer self-collision is not explicitly validated; relies on path planner avoiding immediate self-intersection"
- (b) Stage 6 Level 2 改为 incrementally updated BVH（per-path-point append），工程量 +3 天
- (c) Stage 4 path generation 阶段增加 "outward-spiraling" 约束，确保后续 bead 永远在已打印 bead 的外侧

我推荐 (a) + (c) 组合。

### 6.2 path-level IK 可达性 vs Pass 3 的 pointwise p_ik 的 gap（病灶 A 重申）

Stage 2 用 p_ik(v) 作 field weight 引导层避开 IK 困难区，但 Stage 5 DP 才检查真实的路径连续性。如果在 Pass 3 没有"邻域分支一致性"指标，p_ik 引导出来的层在 Stage 5 仍可能整层 DP 失败。

**你需要在 Pass 3 增加 branch_consistency 项**：
```
p_ik_v6.2(v) = min over (ψ, q) of J_ik
              + λ_consist · branch_volatility(v)
```
其中 `branch_volatility(v)` = 在 v 的 1-邻域内，最优 branch 的"切换次数"或"主导比例"。

这是 v6.2 应该加的，工程量约 1 天，但效果显著。
