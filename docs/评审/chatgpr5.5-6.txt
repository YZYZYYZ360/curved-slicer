# Q8：12 个实验的实际跑时间，Week 12 够不够？

**判定：Week 12 单独不够。必须从 Week 10–11 开始预跑。**

你的估算 `12 runs × 30 min ≈ 6h` 是**理想无错版**。真实情况更接近：

```text
最终正式跑表：6–10 小时
调参 / debug / 重跑：24–48 小时
整理图表 / 修异常 case：1–2 天
```

所以 Week 12 不能承担“第一次跑完整矩阵”。Week 12 应该只做：

```text
final frozen run
表格生成
图生成
论文写作
异常解释
```

v6 本身已经把 Stage 6 定义为三层验证，尤其 Level 3 是 post-quintic dense validation，这一步本来就是慢路径；同时你自己列过 Pitfall 6 和 Pitfall 8：dense validation 会膨胀到 10k–100k 帧，权重调参也会扩大实验规模。 

---

## 推荐实验矩阵

不要叫 “4 baselines × 3 models”。应叫：

```text
4 methods × 3 models
```

其中真正 baseline 是前三个，第四个是 proposed：

```text
M0: planar_z
M1: dijkstra_geom
    α=0, β=0, γ=0, δ=0
    只用 bottom-source weighted distance / shortest distance

M2: dijkstra_mfg_no_ik
    α,β,γ enabled, δ=0
    有 clearance/orientation/curvature bias，无 IK field

M3: proposed_ik
    α,β,γ enabled, δ=δ*
    有 pointwise IK-aware scalar field
```

`v4 PDE` 不放进这个 12-run 主矩阵。它只做 qualitative failure comparison，否则 Week 12 会爆。

# Q9：raster fallback 的 plane spacing 怎么和 geodesic mode 保持一致？

**判定：所有 mode 使用同一个 `line_spacing_mm` 作为目标间距。不要让每个 component 自由自适应。**

你担心的是对的：如果 geodesic component 用 0.8 mm，raster component 自己根据 PCA 变成 0.5 或 1.2 mm，层内打印质量会不一致，实验指标也不可比。

---

## 推荐原则

统一定义：

```yaml
path:
  line_spacing_mm: 0.8
  resample_step_mm: 0.2
  spacing_policy: "constant_target_surface_spacing"
```

无论是 geodesic mode 还是 raster fallback，目标都是：

```text
target surface spacing = line_spacing_mm
```

v6 Stage 4 本来已经定义了 geodesic distance、等值线、stitching 和 0.2 mm 等步长重采样；raster fallback 应该只是失败替代，不应该改变路径间距定义。

---

## geodesic mode

在 layer component 上算测地距离 `d_geo(p)`，取：

```text
d_geo(p) = i * line_spacing_mm
```

这很自然，因为 `d_geo` 本身是 surface distance。

---

## raster fallback mode

对 component 做 PCA，得到 raster plane normal `e1`。定义：

```text
s(p) = dot(p, e1)
```

然后用一族平面：

```text
dot(x, e1) = s0 + i * Δs
```

切 layer mesh。

问题是：`Δs = line_spacing_mm` 是**空间投影间距**，不一定等于曲面上的真实间距。曲面上真实间距近似为：

```text
surface_spacing ≈ Δs / ||Proj_T(e1)||
```

其中 `Proj_T(e1)` 是 `e1` 在曲面切平面上的投影。如果 `e1` 接近局部法向，`||Proj_T(e1)||` 很小，实际路径间距会变大，导致漏填。

---

## 实用方案

对每个 component 计算：

```text
g(p) = ||Proj_Tp(e1)|| = sqrt(1 - dot(e1, n(p))^2)
```

然后取：

```text
g_med = median(g(p))
g_p10 = percentile_10(g(p))
```

推荐：

```text
Δs = line_spacing_mm * clamp(g_med, 0.5, 1.0)
```

这不是“自由调间距”，而是把 plane spacing 转换成接近目标 surface spacing 的补偿。所有 component 的目标仍然是同一个：

```text
target_line_spacing_mm
```

只是平面间距为了实现这个目标做了几何补偿。

---

## fallback 判定

对每个 component 先尝试 geodesic + stitching。通过以下条件则保留 geodesic：

```text
closed_loop_ratio >= 0.95
open_endpoint_count <= 2
max_endpoint_gap <= 1.5 * resample_step_mm
coverage_gap_p95 <= 1.5 * line_spacing_mm
self_intersection_count == 0 或低于阈值
```

否则该 component 走 raster fallback。

注意：**按 component fallback，不按整层 fallback。**

```text
layer 17 component 0: geodesic
layer 17 component 1: raster_fallback
layer 17 component 2: skipped_small_component
```

---

## raster fallback 通过标准

raster 生成后也要评估实际 spacing：

```text
spacing_mean_mm
spacing_p95_mm
spacing_max_mm
```

接受条件：

```text
spacing_p95_mm <= 1.5 * line_spacing_mm
spacing_max_mm <= 2.0 * line_spacing_mm
```

如果不通过：

```text
Fallback 1:
  Δs *= 0.75

Fallback 2:
  component 按 normal clustering 分成 patch，再 raster

Fallback 3:
  标记 PATH_FAIL，不假装成功
```

毕业版可以不实现 normal clustering，但至少要有 Fallback 1 和 PATH_FAIL。

# 最终回答

Q8：**Week 12 不够第一次跑 12 个实验。** Week 10–11 必须预跑，Week 12 只做 frozen final matrix、补跑、图表和论文。实际准备 24–48 小时用于重跑是合理的。

Q9：**raster fallback 使用同一个 `line_spacing_mm` 作为目标 surface spacing。** Plane-family intersection 可以用 PCA，但 plane step 要按 `||Proj_T(e1)||` 做几何补偿；fallback 是 component-level，不是 whole-layer-level。

Q10：**必须冻结 `trajectory.csv` 和 `diagnostic.json` schema。** `trajectory.csv` 记录 dense frame / keyframe 的 joint、TCP、status、wire、segment；`diagnostic.json` 记录 run-level summary、field/layer/path/IK/collision/transition/failure/height-sweep metrics。Week 10 冻结 `v1.0`，之后所有实验不再改字段。
