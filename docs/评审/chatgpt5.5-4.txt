## 先给结论

v6 **可以作为 10–12 周保毕业工程方案推进**，但还有 6 个必须改写的点。它们不是让方案作废的 conceptual flaw，但如果不改，CLI #2 会在实现时掉坑，论文也会被审稿人抓住。

最重要的一句：

> **v6 不能再说“把 C1–C4 翻译成边权后，距离场天然避开困难区域”。只能说“用边权偏置 scalar field，随后用后验验证量化 C1–C4 违反”。**

你当前 v6 的目标、硬件、L4 交付、10–12 周预算、mao stress test、KRL offline 优先这些设定是合理的。但 Stage 2–6 的工程实现要按“软引导 + 硬验证”来组织，而不是按“边权等价于制造约束”来组织。

# A. v6 剩余根本问题

## A1. 硬约束被软边权替代，这是 v6 最大剩余问题

你把 C1–C4 翻译成 `p_clear, p_orient, p_curv, p_ik` 边权，然后用 Dijkstra 生成 `D_final`。这在工程上有用，但它不是约束满足算法。只要没有替代路径，Dijkstra 仍会穿过高代价区域。也就是说：

```text
高 penalty ≠ 禁止
有限 penalty ≠ collision-free
有限 penalty ≠ IK feasible
有限 penalty ≠ support-free
```

修正方式：

```text
soft penalty:
    p_clear, p_curv, p_ik 用于引导 scalar field

hard mask:
    truly impossible regions 用 binary infeasible mask 标出来

post validation:
    C1/C2/C3/C4 全部以后验统计为准
```

论文写法必须改成：

> The scalar field is manufacturability-biased, not manufacturability-guaranteed.

CLI #2 要实现两个输出：

```text
field_metrics.json:
    mean_penalty
    max_penalty
    high_penalty_voxel_ratio
    hard_infeasible_ratio

validation_report.json:
    C1_support_violation_ratio
    C2_ik_failure_ratio
    C3_collision_failure_ratio
    C4_curvature_violation_ratio
```

---

## A2. `C(x)=nearest distance to surface` 不是喷头 clearance

你现在 Stage 1 说 `Clearance field C(x) = nearest distance to surface`，Stage 2 用它构造 `p_clear`。这有两个问题：

第一，nearest distance to final surface 不是 nozzle-body clearance。喷头是有方向的圆柱/胶囊，clearance 应该依赖姿态：

```text
clearance(x, R_tool) = distance(nozzle_body(x, R_tool), printed_or_final_geometry)
```

第二，C3 真正关心的是“相对于已打印部分”的碰撞，而不是相对于最终模型表面的距离。最终模型表面附近本来就是要接近的地方，用 final-surface distance 直接当喷头 clearance 会误导。

修正方式：

Stage 2 的 `p_clear` 只能定义成 **geometric cavity risk**：

```text
p_cavity(v) = max(0, r_n + margin - local_opening_radius(v))²
```

真正 C3 放到 Stage 6：

```text
FCL capsule/cylinder vs accumulated printed mesh
```

论文不要把 `p_clear` 写成 collision-free 证明，只写成 collision-risk prior。

---

## A3. C1 support-free 没有被 scalar field 自动保证

从底部出发的 Dijkstra field 会产生一个单调顺序，但这不等价于 ASN 粘合。等值面之间可能局部距离过大、层面碎裂、最大组件过滤后局部缺支撑、Marching Cubes 插值后接触关系改变。你原始 v4 里 C1 是离散 ASN 约束；v6 现在没有显式构造 ASN，只是借 scalar field 隐含顺序。

修正方式：

Stage 3 后必须做 layer support check：

```text
for each sampled point p on layer k:
    project/search nearest points on layer k-1
    support_ok if distance(p, layer_{k-1}) <= support_radius
              and normal/contact angle <= threshold
```

输出：

```text
support_violation_heatmap.ply
support_pass_rate_per_layer.csv
```

论文写法：

> C1 is evaluated post hoc by local inter-layer support tests.

不要写：

> C1 is encoded by shortest-path field.

---

## A4. `D_final ∈ [0,1]` 与 `iso = k × layer_height` 单位冲突

你写 Pass 4 把 `D_final` 归一化到 `[0,1]`，Stage 3 又写 `Marching cubes at D_final = k × layer_height`。这在单位上不对。

修正方式：

保留两个版本：

```text
D_mm      # 有物理单位，Dijkstra 累积距离，单位 mm
D_norm    # 仅可视化，D_mm / max(D_mm)
```

等值面只能用：

```text
iso_k = k * h_layer_mm
MC(D_mm, iso_k)
```

`D_norm` 只用于图和论文伪彩色，不参与层高。

CLI #2 必须在代码里禁止用 normalized field 切片：

```cpp
assert(field.unit == FieldUnit::Millimeter);
```

---

## A5. per-voxel `tool_x = path_tangent_estimate` 不稳定

Stage 2 Pass 2 里你用 `tool_z = -n, tool_x = path_tangent_estimate, tool_y = z × x` 估每个 voxel 的工具姿态；但 path tangent 在路径生成前并不存在。即使估一个局部 tangent，也会在等值面奇异点、碎片边界、闭合曲线转角处不连续，导致 `p_ik` 产生人为跳变。

修正方式：

Stage 2 不要固定完整工具姿态，只固定 tool axis：

```text
tool_z(v) = -normalize(∇D0(v))
yaw ψ remains free
```

然后构造稳定参考轴：

```text
ref = world_x
if |dot(ref, tool_z)| > 0.9:
    ref = world_y

tool_x0 = normalize(ref - dot(ref, tool_z) * tool_z)
tool_y0 = cross(tool_z, tool_x0)
Rψ = rotate_about(tool_z, ψ) * [tool_x0, tool_y0, tool_z]
```

真正 path tangent 放到 Stage 5 路径点上处理，不放在 voxel IK field 阶段。

---

## A6. “每层最大组件”不能静默删几何

Stage 3 写“连通性 filter，每层最大组件；最大组件 <80% 整层面积标 BROKEN”。问题是：保留最大组件会直接丢几何。对于 bunny 可能没事，对于 armadillo 四肢、耳朵、尾巴或 mao 头发碎片，丢掉小组件会让覆盖率虚高。

修正方式：

```text
不要默认删除小组件。
先全部输出。
再按 area ratio 标注：
    MAIN
    SMALL_COMPONENT
    BROKEN_LAYER
```

只有在路径生成阶段允许：

```text
--component-policy all | largest | area-threshold
```

论文指标必须报告：

```text
deleted_area_ratio
component_count_per_layer
broken_layer_count
```

---

## A7. `igl::exact_geodesic` 等值线不一定是可打印填充路径

Stage 4 复用 v4 §13，用每层 mesh 上的测地距离等值线生成 polylines。这会生成“曲面上的线”，但不一定覆盖一个曲面层的沉积面积。FDM 要么是 shell-only，要么需要 raster/spiral/offset infill。单纯 geodesic iso-curves 可能出现：

```text
路径间距不均
局部漏填
闭合区域内部没有 infill
边界附近断裂
多组件层路径顺序混乱
```

修正方式：

毕业版先明确目标：

```text
目标不是完整实体填充强度优化；
目标是曲面层表面的可执行 deposition curves。
```

但工程上至少要做两个 path mode：

```text
mode A: geodesic-contour shell paths    # 复用 v4 §13
mode B: projected-grid raster paths     # fallback，稳定出路径
```

如果 geodesic stitching 失败，自动 fallback 到 raster。

---

## A8. Stage 0 的 Hausdorff ≤0.5mm 与 dilation 可能互相矛盾

你要求 decimation 去除 `<0.5mm` 细节、薄壁 dilation，又要求 `Hausdorff(M,M')≤0.5mm` 和法向偏离 ≤5°。薄壁 dilation 很容易让 Hausdorff 超过 0.5mm，局部 smoothing 也可能让法向超过 5°。这两个硬约束不能同时绝对化。

修正方式：

分两类报告：

```text
geometry_clean:
    hole filling, manifold repair, decimation
    should satisfy Hausdorff <= 0.5mm

manufacturing_regularized:
    optional dilation / smoothing
    may violate Hausdorff, but must report deviation
```

论文不要写“硬约束必满足”，写：

```text
bounded regularization, reported by Hausdorff / normal / volume / silhouette metrics
```

# B. 10 个 Pitfalls 逐条评估

| Pitfall                | 判定  | 影响交付？ | 处理方式                                                                                                                             |
| ---------------------- | --- | ----: | -------------------------------------------------------------------------------------------------------------------------------- |
| 1. Pass 2 鸡生蛋          | 真问题 |     中 | 不迭代。只做两次：`D0 → p_ik → D_final`。如果 `D_final` 与 `D0` 偏差过大，降低 `δ`，不做无限迭代。                                                           |
| 2. `p_ik` 不连续          | 真问题 |     高 | 对 `p_ik` 做 winsorize + Gaussian/median smoothing；`δ` 做上限；保留 hard infeasible mask。                                                |
| 3. yaw 采样密度            | 真问题 |     中 | Stage 2 用 12；Stage 5 用 adaptive：先 12，失败段局部升到 24。不要全局 24。                                                                         |
| 4. cyclic DP 难度        | 真问题 |     中 | 先实现 open DP；闭合路径用 endpoint repair；Week 7 再实现 true cyclic。                                                                        |
| 5. FCL printed BVH 增量  | 被高估 |     中 | 不做 per-point 增量 BVH。按 layer/block rebuild BVH，先保证正确。                                                                             |
| 6. post-quintic FCL 爆炸 | 真问题 |     高 | 分层验证：SDF prefilter 全帧，FCL 只查 high-risk frames + fixed stride；失败段局部加密。                                                            |
| 7. mao 语义损失            | 真问题 |     中 | 用 Hausdorff/normal/volume + silhouette overlap；加原图/处理后对比。不要证明“还像 mao”，只报告 shape deviation。                                       |
| 8. 权重调参                | 真问题 |     高 | 不做 4D grid。固定 `α,β,γ`，只消融 `δ`；再做 one-factor ablation。                                                                            |
| 9. bunny 实机兜底          | 真问题 |     高 | 准备 “rounded cube / small bunny” fallback。论文承诺“至少一个 physical print”，不要只押 full bunny。                                              |
| 10. baseline           | 真问题 |     中 | 至少 3 个 baseline：planar slicing、pure geometric Dijkstra、v6 without IK term。v4 PDE baseline 可作为 failure comparison，不作为唯一 baseline。 |

你漏掉的额外 Pitfalls：

1. **Dijkstra 内存爆炸**：0.5mm voxel 对 mao 可能太大。CLI 默认应支持 `--voxel 1.0`、`--voxel 0.8`、`--voxel 0.5` 三级。
2. **单位/坐标系错误**：STL 坐标、机器人 base、TCP、喷头轴、KRL 坐标常常是最大工程坑。必须 Week 1 就做 frame audit。
3. **路径数量爆炸**：每层多个 component、多条 contour，会让 IK DP 输入远大于预期。必须有 path simplification。
4. **KRL 只输出 OK segment 会造成轨迹不连续**：OK segment 之间需要 retract / travel move，否则实际机器人无法从一个 OK island 跳到另一个。
5. **FDM extrusion 未建模**：线宽、流量、速度、启停、回抽没有进入算法。论文要写为 geometric/kinematic validation，不写 full process optimization。

# E. 权重与实验策略

不要做 4D grid search。CLI #2 按这个顺序：

```text
Step 1:
    α = 1.0, β = 0.3, γ = 0.1, δ = 0
    跑 geometry-only

Step 2:
    固定 αβγ，只扫 δ:
        δ = 0, 0.25, 0.5, 1.0

Step 3:
    选一个 δ*，做 ablation:
        no_clearance
        no_curvature
        no_ik

Step 4:
    mao 不调参到成功，只报告失败定位
```

验收指标优先级：

```text
P0:
    程序不崩
    layer coverage
    component count
    IK pass rate
    collision failure ratio
    KRL OK segment length

P1:
    layer thickness error
    support pass rate
    curvature violation
    runtime

P2:
    height-sweep correlation
    silhouette similarity
```

# F. 交付降级线

12 周内必须有清晰降级，不然会拖死。

## L4 full target

```text
bunny physical print or robot dry-run + extrusion
armadillo full dry-run
mao annotated stress test
IK-aware scalar field ablation
FCL validation
KRL export
```

## L3 acceptable graduation target

```text
bunny full dry-run + small physical print
armadillo dry-run with failure heatmap
mao layers + failure heatmap only
IK-aware ablation
KRL export for bunny OK segment
```

## L2 emergency target

```text
bunny geometry layers + IK + KRL
armadillo geometry layers + IK report
mao only scalar field visualization
no physical print, but robot dry-run video
```

## 必须避免的假成功

```text
不要生成完整 KRL 但中间有 IK_FAIL/COLLISION_FAIL
不要删除小组件后报告 coverage 很高
不要把 δ 调到层面变形严重还说 IK-aware 有效
不要把 mao failure 写成 algorithm success
不要把 SDF clearance 写成 FCL collision-free
```

# 给 CLI #2 的最终执行指令

1. **先跑通 geometry-only Dijkstra curved slicing，不接 IK。**
   没有稳定 layers，不允许进入 IK DP。

2. **`D_mm` 是唯一切片场。`D_norm` 只能可视化。**

3. **IK-aware field 只做 pointwise margin。**
   不能把它当路径级可行性证明。路径级可行性由 DP + validation 决定。

4. **所有 constraints 都以后验 report 为准。**
   Field 负责 bias，validator 负责判定。

5. **所有失败都要落盘。**
   `IK_FAIL`、`COLLISION_FAIL`、`BROKEN_LAYER`、`SING_RISK`、`VEL_FAIL` 都要有 index、位置、层号、路径号。

6. **mao 的成功标准是完整失败定位报告，不是全 OK trajectory。**

7. **physical print 只押一个小模型，不押 mao，不押完整 armadillo。**

## 最后判断

v6 没有必须推翻的根本 conceptual flaw，但必须从“约束翻译成边权”改成：

> **制造性加权 scalar field 生成候选曲面层；轨迹级 IK、support、collision、curvature 用后验验证判定；复杂模型输出 annotated infeasibility report。**

这样写，10–12 周是 aggressive but executable。
如果 CLI #2 严格按上面周计划做，优先保证 Week 2–6 的 geometry + IK dry-run 主链路，后面的 FCL、实机、mao、ablation 都有降级路径，毕业风险可控。
