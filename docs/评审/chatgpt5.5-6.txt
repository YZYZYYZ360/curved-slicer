## 结论

**v6.1 可以作为 CLI #2 的实施基线，但现在还不能“冻结”。**
不是因为算法方向错，而是因为文档里还有几处会让执行者写错、让实验矩阵不可比、或让论文 claim 自相矛盾的地方。

# 一、P0 必须改：不改会影响实现或论文成立

## P0-1：C1–C4 的措辞还残留“硬约束必须满足”的影子

你文档里一方面写：

> Scalar field is manufacturability-biased, not manufacturability-guaranteed.

这是对的；但另一方面又写“四约束，任何曲面层算法必须满足”，并列出 C1 ASN、C2 IK、C3 喷头碰撞、C4 曲率干涉。这个表述仍然容易让人理解成：**边权生成的层天然满足 C1–C4**。你的方案实际是“soft bias + post validation”，不是 hard constraint solver。

建议把标题从：

```text
四约束（任何曲面层算法必须满足）
```

改成：

```text
四类可制造性指标（用于 bias 与 post-validation）
```

并补一句：

```text
C1–C4 are not guaranteed by the scalar field. They are evaluated by post-validation; failed regions are either rejected, connected by wire-off transition, or reported.
```

否则审稿人会问：既然 C3 是硬约束，为什么还需要 collision fail ratio？既然 C2 是硬约束，为什么还需要 IK_FAIL？

## P0-2：penalty 的单位和尺度没有归一化，αβγδ 会失控

现在边权写成：

```text
w = ||u-v|| × [1 + α·p_clear + β·p_orient + γ·p_curv + δ·p_ik]
```

但这些项的量纲完全不同：

```text
p_clear: mm² 或 cavity penalty
p_orient: [0,1]
p_curv: 1/mm²
p_ik: 关节限位倒数 + σ_min 倒数 + workspace margin 倒数
```

这会导致一个问题：**δ 的数值没有物理意义，ablation 也不可解释。**
比如 `p_ik` 若因为 `1/(σ_min+ε)` 爆到几百，δ=0.25 就可能压倒所有几何项；而 `p_curv` 可能非常小，γ 怎么调都没效果。

必须在 Stage 2 加一个标准化层：

```text
p_i_raw(v)      # 原始 penalty
p_i_clip(v) = winsorize(p_i_raw, p05, p95)
p_i_norm(v) = clamp((p_i_clip - p05) / (p95 - p05 + eps), 0, 1)
```

最后边权只用：

```text
p_clear_norm, p_orient_norm, p_curv_norm, p_ik_norm
```

`diagnostic.json` 里要同时记录 raw 分布和 norm 分布：

```json
"penalty_stats": {
  "p_ik_raw_p95": ...,
  "p_ik_norm_mean": ...,
  "p_curv_raw_p95": ...
}
```

这件事必须进 plan，否则 Week 10 的 δ ablation 没有解释力。

## P0-3：`p_orient = 1 - |edge · build_direction|` 会把层面推回接近平面切片

这个是当前算法里最大的“隐形数学问题”。

你 Stage 2 的方向项写的是：

```text
p_orient(u,v) = 1 - |normalize(v-u) · build_direction|
```

这会鼓励 Dijkstra 距离场沿全局 build direction 增长。结果是：**β 越大，越像 Z 向平面切片**。它和“曲面层随模型形状弯曲”的目标有冲突。

建议改成局部 preferred growth direction：

```text
B(v) = normalize((1 - η) * build_direction + η * N_smooth(v))
p_orient(u,v) = 1 - |normalize(v-u) · B(v)|
```

其中：

```text
η = 0.2 ~ 0.5
```

这样 β 才是在“保持从底部推进”和“贴合局部形状”之间折中，而不是单纯把场拉回全局 Z。

实验也要加一个小 ablation：

```text
η = 0, 0.3
```

不用放主表，但至少 internal smoke test。否则 proposed 可能跟 planar-Z 差异不大。

## P0-4：`cavity_radius(v)` 没有定义，CLI #2 无法实现

你已经正确把 `p_clear` 降级成“cavity risk”，而不是真正喷头 clearance；但公式里用了：

```text
p_clear(v) = max(0, r_n + margin - cavity_radius(v))²
```

问题是：`cavity_radius(v)` 没定义。不同实现会完全不同。

建议给 CLI #2 一个可实现的近似定义，不要追求完美：

### 版本 A：局部开口风险，低成本

对每个 surface-near voxel `v`：

```text
for directions d_i on sphere:
    cast ray from v along d_i
    measure first opposite-surface hit distance l_i
cavity_radius(v) = percentile_20(l_i) / 2
```

这近似“喷头附近是否有狭窄开口”。

### 版本 B：SDF/local feature size 近似，低实现风险

```text
cavity_radius(v) = abs(SDF_medial_like(v))
```

但这个会在真实表面附近很小，容易误判，需要只在 concave regions 上启用。

我建议采用 A 的简化版，方向数先用 32 或 64。最终论文写成：

```text
local opening-radius proxy
```

不要叫 exact clearance。

## P0-5：Dijkstra 场没有平滑步骤，Marching Cubes 层会有网格锯齿

你现在从 `D_final_mm` 直接 Marching Cubes。Dijkstra 图距离场是 piecewise graph metric，特别是在 26 邻域体素图上，会有明显方向量化。路径后面再怎么 smooth，也救不了层面锯齿。

你之前砍掉 PDE 是对的，但不能完全不平滑。建议加入 **bounded field smoothing**：

```text
D_s = D_final
repeat T=3~10:
    D_tmp = edge-aware_laplacian(D_s)
    D_s(v) = clamp(D_tmp(v), D_final(v)-ε, D_final(v)+ε)
```

推荐：

```text
ε = 0.25 * layer_height_mm ~ 0.5 * layer_height_mm
```

切片用：

```text
D_slice_mm = D_s
```

但保留：

```text
D_final_mm 原始场
D_slice_mm 平滑后场
field_deviation_from_Dfinal
```

论文写法：

```text
bounded scalar-field smoothing is used only to reduce voxel anisotropy; all manufacturability metrics are re-evaluated after layer extraction.
```

不加这一步，bunny/armadillo 的层面图可能会很难看。

## P0-6：printed state 的更新规则没有写清楚，C3 intra-layer 会被实现错

你写了 C3 包含同层自碰撞，Stage 6 也有 printed BVH / capsule sampling，但没有定义 printed state 的更新时机。

CLI #2 必须按下面规则实现：

```text
printed_state initially = platform or empty previous material

for layer k:
    for component c in scheduled order:
        for path p in scheduled order:
            validate nozzle(path p) against printed_state
            if OK and wire_on:
                add swept bead mesh of path p to printed_state
            else:
                do not add failed path
        validate transition against printed_state
```

否则很容易出现两种错误：

1. 只检查 previous layers，漏掉同层前面已经打印的材料。
2. 直接拿 final mesh 当 obstacle，把本来还没打印的材料也当成障碍，误杀大量路径。

这个规则必须写入 Stage 6。

## P0-7：KRL “仅 PRINT_OK” 与 transition 段导出逻辑矛盾

你文档写：

```text
KRL .src/.dat（仅 PRINT_OK segments）
```

但 TransitionPlanner 生成的 RETRACT/TRAVEL/APPROACH 段不是 PRINT_OK，它们是 wire_off 的有效运动。如果 KRL 真的只导出 PRINT_OK，机器人无法从一个打印段移动到下一个打印段。

改成：

```text
KRL exports connected executable blocks:
    PRINT frames with status=OK and wire_on=1
    VALID_TRANSITION frames with wire_on=0
It never exports IK_FAIL / COLLISION_FAIL / TRANSITION_FAIL frames.
```

也就是说 status 枚举里最好新增：

```text
TRANSITION_OK
```

或者保持 status=OK，但用：

```text
motion_type = RETRACT / TRAVEL / APPROACH
wire_on = 0
```

并在 KRL writer 里明确：

```text
export if status == OK and motion_type in {PRINT, RETRACT, TRAVEL, APPROACH}
```

不要写“仅 PRINT_OK”。

## P0-8：时间参数化和 DP 的 `Δt` 依赖关系要改清楚

Stage 5 写：

```text
硬约束：|Δq| ≤ qdot_max·Δt
Δt = max(d_cart/v_target, |Δq|_max/qdot_max)
```

这里有循环：DP 需要 `Δt` 判定转移是否可行，但 `Δt` 又依赖选出来的 `Δq`。

推荐实现：

### DP 阶段

只用 Cartesian 预估时间：

```text
Δt_cart = d_cart / v_target
```

硬约束改成软一点：

```text
if |Δq| > qdot_max * Δt_cart * stretch_limit:
    reject
```

其中：

```text
stretch_limit = 2~4
```

意思是允许后续 time parameterization 放慢速度。

### time parameterization 阶段

再正式计算：

```text
Δt_i = max(
    d_cart_i / v_target,
    max_j |Δq_j| / qdot_max_j,
    sqrt(max_j |Δ²q_j| / qacc_max_j)
)
```

否则 DP 会因为固定打印速度过早拒绝很多其实可以“慢一点通过”的转移。

## P0-9：五次多项式不能“每个路径点端点零速度”

你计划中“5 次多项式插值到 4ms 周期”是对的，但不能在每个 polyline waypoint 都设零速度。那会导致机器人每 0.2mm 停一次，轨迹完全不可打印。

正确做法：

```text
path start / path end:
    v = 0

intermediate waypoints:
    velocity estimated by finite difference or chord-length parameterization
    acceleration continuous if possible
```

如果时间不够，不要硬做完整 quintic。更稳的是：

```text
joint-space linear interpolation + velocity/acceleration smoothing filter + dense validation
```

论文里不需要强调 quintic 的高级性，重点是“time-parameterized and post-validated”。

## P0-10：mao_regularized “trajectory 全 OK”必须加 gate，不要直接写成默认目标

文档里同时写了两个东西：

* mao_regularized 是 L4 目标，trajectory 全 OK；
* 最大风险是 mao_regularized full OK “可争取，不可保证”，有 L4/L3/L2 降级。 

这不冲突，但要写成 gate：

```text
mao_regularized enters full dry-run only if:
    pointwise IK success > 95%
    layer broken ratio < 5%
    path generation success > 95%
    cavity high-risk voxel ratio < threshold
    support pass rate > threshold
```

否则 CLI #2 可能会在一个明显不可行的 mao_regularized 上硬跑 DP/FCL，浪费一周。

建议添加：

```text
If mao_regularized fails the preprocessing gate, increase regularization or report as L3 instead of attempting full trajectory OK.
```
